How each block works IN THE RTL

March notation

⇑ walks addresses 0 → 63, ⇓ walks 63 → 0, and ⇕ means either (this RTL walks up). (r0,w1) means: at each address, read and expect all zeros, then write all ones. MATS+ = ⇕(w0) ⇑(r0,w1) ⇓(r1,w0) = 5 operations per word. March C− = ⇕(w0) ⇑(r0,w1) ⇑(r1,w0) ⇓(r0,w1) ⇓(r1,w0) ⇕(r0) = 10.

Sequencer (mbist_ctrl.v)

step indexes the algorithm's element list, acnt counts addresses, and opi picks the operation inside an element. One element decoder serves both algorithms: algo = 1 maps steps 0–5 to elements 0–5; algo = 0 maps steps 0, 1, 2 to elements 0, 1, 4. MATS+ is a shorter walk through the same table.

Read-compare pipeline

The SRAM registers dout, so a read issued in cycle N delivers data in cycle N+1. The engine copies the expected value, address and element into chk_* and compares one edge later. After the last element it spends 3 DRAIN edges, so the final read is still compared. Tick the what-if box above to see what goes wrong without the shadow.

First-failure latch

Only the first mismatch is stored: fail_addr, the word read (fail_got), the word expected and the element. The test still runs to the end. Real silicon does the same: the latched address feeds repair (spare-row allocation) rather than a full fail bitmap.

Fault injector (sram_faulty.v)

The fault is set by module inputs, so one compiled image sweeps every case. SA0/SA1 force the victim bit on the read path. TF↑/TF↓ block the victim bit's 0→1 or 1→0 change on a write. CFin/CFid act when a write changes the aggressor bit: the victim bit is inverted or forced. AF makes the aggressor address decode to the victim's word.

Testbench (tb_mbist.v)

For each of the 12 cases and both algorithms it resets, clears the memory, pulses start for one cycle and waits for done. The table records whether fail was set. The fault-free control must stay clean, or the run stops with FATAL. sram_top.v (the synthesisable wrapper with the functional-port mux) is not in this loop.

What a production memory adds NOT IN THIS RTL · NEXT STEPS

This project models the memory at the pin contract of a compiler macro and tests it with a single-port march BIST. Tick Real-silicon view above to see where these parts would sit. They are design notes; the simulation does not model them.

6T array and periphery

A real array is 6T bitcells on word lines and bit-line pairs, with precharge, sense amplifiers, a column mux and write drivers. Faults come from that physics (opens, shorts, weak cells), and the fault models here are their logical abstractions.

Test access

On a chip, start/algo and the fail_* registers are reached through JTAG or an IEEE 1500 wrapper, and one BIST controller often tests many memories.

Repair (BISR)

The first-failure address goes to redundancy analysis, which maps the failing row to a spare row and blows fuses (or stores the map) so the remap is applied at every boot.

ECC

SECDED Hamming (39,32) on the read path corrects single-bit errors in the field. BIST normally runs with ECC bypassed so it sees raw cell faults. Listed under Extensions in the README.

More fault classes

Data-retention faults need a pause element before reading. State coupling faults (a cell disturbed only while a neighbour holds the opposite value) need checkerboard and other data backgrounds, because all-0/all-1 words never put two bits of a word in opposite states.
